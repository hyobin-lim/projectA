# 기술 노트

## 자산 로컬화 및 경로 변환 (완료)
`mental_health_portfolio/index-1.html`에서 발견되는 절대 URL을 `mental_health_portfolio/` 디렉토리 내의 로컬 자산을 올바르게 가리키는 상대 경로로 성공적으로 변환하는 작업은 완료되었습니다. 이 과정에서 에이전트(Gemini CLI)는 로컬화가 필요한 절대 자산 경로와 원본 다운로드 URL, 권장 로컬 대상 경로를 제공했으며, 사용자는 이를 기반으로 자산을 다운로드하여 배치했습니다. 루트 `index.html`에서 사용되는 상대 경로 구조가 이 변환의 주요 가이드 역할을 했으며, 모든 변환에 일관성 있게 적용되었습니다.

## CSS 및 JavaScript 에셋 번들링 실패 (2026-02-11)
*   **문제 현상**: 페이지 성능 최적화를 위해 CSS 및 JavaScript 파일 번들링을 시도했으나, 과정에서 여러 기술적 문제로 인해 실패했습니다. 특히, `read_file` 도구로 특정 CSS 파일(`aos.css` 등)을 읽을 때 파일의 전체 내용이 아닌 일부만 반환되는 문제가 발생하여, 불완전한 번들 파일이 생성되고 웹사이트 스타일이 깨지는 심각한 오류가 발생했습니다.
*   **해결책**: 현재는 번들링 된 파일(`app.bundle.css`, `vendor.bundle.css` 등) 사용을 중단하고 `index.html`에서 기존의 개별 CSS 및 JavaScript 파일들을 다시 링크하는 것으로 원상 복구한 상태입니다.
*   **교훈**: `read_file` 도구와 같이 파일 내용을 정확히 읽어오는데 제한이 있는 환경에서는 파일 번들링과 같은 작업을 진행할 때 반환 값의 완전성을 항상 검증하거나, 더욱 안정적인 파일 처리 방식을 모색해야 합니다. 이 문제 해결 전까지는 번들링 재시도를 보류합니다.

## `cmpn_logo.png` 모바일 GNB 로고 여백 문제 (2026-02-11)
*   **문제 배경**: 모바일 화면에서 GNB (Global Navigation Bar) 내 `cmpn_logo.png` 로고 이미지가 너무 크게 표시되는 문제를 해결하기 위해 `portal_contents.css` 파일에 `@media screen and (max-width:960px)` 미디어 쿼리를 추가했습니다. 이 미디어 쿼리는 로고 이미지의 `width`, `height`, `max-width`, `margin-bottom` 속성을 강제하여 이미지 자체의 크기는 적절하게 조정되었습니다.
*   **현재 문제**: 하지만 이 CSS 규칙 적용 이후, GNB 창 내부에서 로고 이미지의 위아래로 불필요한 여백이 발생하고 있습니다. 이 여백으로 인해 로고 이미지가 다른 GNB 섹션 요소들과 시각적으로 일관되지 않게 배치되어 어색해 보입니다.
*   **필요한 작업**: GNB 레이아웃에 부정적인 영향을 주지 않으면서, `cmpn_logo.png` 로고 이미지 주변의 이 불필요한 위아래 여백을 제거하고 GNB 내에서 로고의 배치를 최적화하는 CSS 규칙을 새롭게 분석하고 적용해야 합니다.

## 디버깅 및 문제 해결 노트 (기존 기록 중 관련 있는 내용만 유지)

### JavaScript `alert()`의 렌더링 차단(Rendering Blocking) 현상 (해결 완료)
*   **문제 현상:** JavaScript에서 특정 요소에 CSS 클래스를 추가하여 애니메이션을 유발한 직후 `alert()`를 호출하면, 브라우저가 화면을 다시 그리기(repaint) 전에 스크립트 실행이 멈춥니다. 이로 인해 `alert()` 창이 닫힐 때까지 애니메이션이 시작조차 하지 않는 문제가 발생했습니다.
*   **해결책:** `alert()` 호출을 `setTimeout`으로 감싸 아주 짧은 시간(예: 20ms)이라도 지연시켜 브라우저가 CSS 변경사항을 렌더링할 시간을 확보하도록 하여 해결했습니다.

### `[data-aos]` 속성과 자식 요소의 상호작용 (해결 완료)
*   **문제 현상:** `aos.css`는 기본적으로 `[data-aos]` 속성을 가진 요소에 `pointer-events: none;`을 적용합니다. 이로 인해 애니메이션 대상의 부모 요소에 `data-aos`가 적용되면, 그 안의 모든 자식 요소들(버튼, 링크 등)이 클릭되지 않는 문제가 발생했습니다.
*   **해결책:** 클릭이 되어야 하는 특정 자식 요소에 대해 `pointer-events: auto;` CSS 규칙을 명시적으로 추가하여 부모로부터 상속된 `pointer-events: none;` 스타일을 덮어써서 해결했습니다.
